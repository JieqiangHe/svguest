# svguest

A lightweight in-browser SVG editor for touching up ggplot2/svglite figures (often re-saved by Inkscape). Live at https://jieqianghe.github.io/svguest/ (GitHub Pages serves `main`). Renamed from minisvg in Oct 2026; until 22 Nov 2026 a separate `minisvg` repo serves a redirect page at the old address (jieqianghe.github.io/minisvg/ → /svguest/, keeping query and hash). Versions before the rename used the prefix `msb`; the only traces left are the reads that carry old data over: the `<head>` script moves every `msb*` localStorage key to `sg*` once (an existing `sg` key wins), `idbO` copies an old database (`msbDocs`, `msbChats`, `msbDir`) into the new one when it is first created (`idbM`) and then deletes it, `parse` renames `data-msb-from`/`-to` to `data-sg-…`, and the head pickers and `mgc` still read `…Msb` markers. The redirect repo holds only `index.html`, `404.html` (both `location.replace` to `/svguest/` with query and hash, meta refresh without JS) and a README. A Pages deploy that collides with one in progress fails; its re-run can hang in queued (neither cancellable nor re-runnable), and the next push deploys.

## Repo rules

- The whole app is one file, `index.html` (~100 KB). The repo contains `index.html`, `README.md`, `LICENSE`, `svguest.plugin`, `.claude/` (the TBtools plugin skill), `.gitignore` and `CLAUDE.md`; only `.DS_Store` is gitignored. Do not add test files, build files or other folders.
- Plain JavaScript, no framework, no build step, no dependencies, no CDN. It must work offline and as a static page.
- Commit and push straight to `main`; HTTPS auth fails in this sandbox, so push over SSH (`git push git@github.com:JieqiangHe/svguest.git main`). Do not create branches or PRs unless asked.
- UI text, tooltips, messages and README are English only. Never leave Chinese in the app.
- Help is kept short: one line per action, related keys grouped in one row (condensed Oct 2026).
- Code style: dense and short, no comments, match the surrounding one-liner style. Simplify without changing behaviour; don't refactor unasked.
- README ends at "... Nothing is uploaded." followed by the `**Live: ...**` line, the TBtools-II note and the licensing warning (do not use/trace others' figures as your own). Keep it that short.
- After changing `index.html`, rebuild `svguest.plugin` with the skill, staging with the skill's `scripts/svguest-stage.sh` (it copies `index.html` with the TBtools-only ChatGPT script added, `assets/tbtools-ai.json`, which opts the plugin into the TBtools model, and `assets/siwc.json`; JDK: micromamba env `openjdk_25.0.2`, `~/.local/share/mamba/envs/openjdk_25.0.2/lib/jvm/bin`; TBtools jar: `/Applications/TBtools-II.app/Contents/java/app/TBtools_JRE1.6.jar`) and commit it. Without the jar (a cloud sandbox), see the skill's stub note.

## Architecture (names in index.html)

- `root` is the document `<svg>`; `vb` is its viewBox; `U` = mm per user unit; `Z*k` = screen px per user unit; `tx`,`ty` = pan.
- Undo: MutationObserver records into `pend`; `commit()` pushes a step (stack capped at 200 via `trim`), `revert()` undoes, `quiet(fn)` makes temporary mutations that are not recorded. Multi-commit sequences (Alt+drag copy, transform again, pasteZ, ungroupAll, held arrow keys, AI patch/import) wrap their work in `once(f,j)`: everything `commit()`ed inside collapses into one step (`j` merges into the last existing step, as held arrow keys do).
  - Step names: every step carries `n`, set from `why` (cleared by each `commit`) or, failing that, `guess(records)` (Edit text, Rearrange, Add, Delete, Transform, Edit shape, Page size, Lock, Style, Change). `why` comes from the button's name (`bName`, via the body click handler), the key's action (`AN`, action function → name, filled at startup), the side-panel field, `up()` per drag type (Move, Scale, Rotate, Draw rectangle…), `nudge`, `paste`, `fsz`, `finish`. Merged steps keep the first name. `bar()` writes them into Edit › Undo/Redo ("Undo Nudge"); `undo()` reports "Undo: Nudge". Edit › History (`#mHi` submenu, `hiL()` rebuilds `#mHm` on hover) lists up to 12 redo steps (`fu`, dimmed), the current step (ticked), 25 undo steps and Start; a click undoes/redoes that many steps quietly (`undo(r,1)`) and reports "Went back N steps". `svd` is the undo top at the last save/load (`load` sets null), so undoing back to it clears `dirty`; `dv` counts document versions (for caches such as `hcp`).
- Small helpers: `toS(q)` maps user units to view pixels (the inverse of `toU`), `q45(x,y)` rounds a vector to 45° steps (and returns the step), `cmd(e)` is Ctrl or ⌘.
- Matrices: never use DOMMatrix translate/scale/rotate (float32). Build them from arrays with `mx`, `T`, `S`, `Rot`, `about`. `lm(e)` parses the transform attribute in double precision; `ctm(e)` walks up to root. Write transforms with `setT`. `order(a)` sorts into document order, via a TreeWalker index map when the list has 64+ elements (compareDocumentPosition sorting gets slow on big files).
- Number output: `fm` (8 significant digits), `fc` (fixed 1e-5), `f6`. Untouched elements must serialise byte-identical.
- Bounding boxes:
  - `lbox(e)` is the local box, clipped by clip-path; `bbox(e)` = `mbox(e, parentCTM*lm(e))`.
  - `mbox` recurses for rotated matrices. It is exact for circle/ellipse, line/poly and straight-line paths.
  - Groups with more than 2000 descendants fall back to the loose box for speed.
  - Use `memoize(()=>...)` around batches of bbox calls.
- Selection: `sel`, `setSel(a,noRefresh)`, `refresh()`, `sb` (selection box); handles live in `H`. Locked elements (see Lock below) are filtered out of every selection.
  - Click selects the part under the pointer (`grab`); Ctrl/⌘+click selects its top-level object (`pick`). `ctx` is the group of the selection; Esc climbs it, an empty click resets it to root. Alt+click without a drag (`selBelow`) cycles through the objects stacked under the pointer (uses `elementsFromPoint` via `thru`), reporting "object 2 of 4".
  - Hover: with no drag under the Select, Eyedropper or Text tool, `hoverAt`/`hovCalc` outline in blue (`hud`) the object the pointer is over — its true outline (`outl(e)`: line endpoints, or a path's anchors with C/Q/A sampled at 8 points each via `arcPts`) as polylines, falling back to its bbox for shapes it can't read. Throttled to one calc per animation frame, or a 90 ms timeout when `hit()` last took over 12 ms; hidden over handles, scrollbars, rulers, the Layers button, the text editor or an already-selected object, and Ctrl held switches to the top-level object. Over a Layers row, `hovCalc` takes that row's element instead, so the canvas outline follows the list (and `lyHv` marks the row of the object hovered on the canvas).
  - Right-click opens the context menu (`cmenu`, `#mCM`, entries in `CM`): Cut/Copy/Paste here/Paste in place/Delete, Crop image and Remove crop (only when the selection is one `<image>`; the second only when it carries our crop, `cropK`), Group/Ungroup, z-order, Select the object below, Same fill/stroke, Lock/Unlock all. `cmE` remembers the event so Paste here pastes at the pointer; Ctrl+click (which also fires contextmenu on a Mac) is ignored, so Ctrl+click selection keeps working; the menu closes on outside pointerdown, click, blur, resize or Esc (which doesn't deselect). Actions `cut`, `below`, `pasteHere`, `cropI` (the crop tool, which opens the crop box on the selected photo) and `uncrop` (`cropR` with the whole photo) exist only for the menu.
  - `hit(e)` uses `document.elementFromPoint` with `#mGW`, `#mCap` and the handles set to `pointer-events:none` (`thru(f)` toggles them around any hit-test; elementsFromPoint costs ~35 ms per call on a 150k-element file). Over a filled area, a thin line or small mark painted above within 4 px wins; the search stops after 40 ms.
  - A click on the page background starts a box select, not a move: `bd(t)` recognises a filled rect that is first among its siblings, covers at least a quarter of the page and fully contains another leaf (`down` starts a `band`, and a click without a drag selects the rect).
  - Box select `boxed(c,R,tch)`: whole groups that fit are taken, else it recurses into them; children of a group with over 2000 (`BIG`) children are measured with getBoundingClientRect, and so is every other leaf without a clip-path (`fb(e,V)`: the native box mapped back to user units; groups and clipped elements still go through `bbox`). `refresh()` uses `fb` too when over 300 objects are selected. `lbox` finds a group's clipped child through `hcp(e)`, cached per `dv`. Ctrl/⌘ during the drag maps each hit to its top-level object (`pick`) before deduping. Alt+drag is touch select (`tch`): anything the box intersects is taken too; View › Box select touches (`opts.touch`, `sgTouch`) is on by default, as in Illustrator (the user's choice, Oct 2026, knowing that in a ggplot panel a touching box also grabs every gridline it crosses): a plain drag touches and Alt+drag encloses; turned off, the two swap (`tch` = Alt XOR the option, read when the drag starts; the status line says "N objects touch the box" or "N objects in the box"). Touching works via `touches(e,R)` (a point in `inR`, or an outline segment crossing the rect with the slab test `sr`); always against the drag box itself — `fb` boxes are ~0.001 units off, so testing against the box clipped to them missed every vertical or horizontal line). After 60 ms of dragging, `bandPrev` previews the would-be selection — blue boxes (`D.pv` drawn by `hud`) plus a count in the status line — and switches itself off (permanently for that drag) when measuring takes over 60 ms on a large file.
  - Point editing (`ped`, like Illustrator's direct selection): a click without a drag on a corner handle, or a double-click on a shape, shows the shape's anchors as hollow squares (`data-h=a<i>`) in place of the box handles. Dragging one moves only that anchor plus the curve handles attached to it (`moveA`); Shift gives 45° steps. Esc, a new selection or a click outside ends it. `pmodel(e)` reads rect (rounded ones as arcs), circle, ellipse, polygon/polyline and path (`pparse`: absolute M/L/C/Q/A/Z, with H/V/S/T folded in; null for paths it can't read or over 2000 segments). Results are cached per element in `PMC`, keyed on its `d`/`points` (a 100k-point path was re-parsed on every hover and every `hud()` while point editing, 40 ms each), so callers must treat the model as read-only (the anchor drag copies `o` before `moveA`). A closed subpath's last point that repeats its start is linked to it (`anchorsOf`). On the first real drag a rect, circle or ellipse becomes a `<path>` (`toPath`, keeping id and attributes; `kps`/`kpr` keep class-styled paint). The skew mode tried before was dropped.
  - Bending a line (asked for by the user, Oct 2026): one selected two-point line or arrow shows a diamond (`data-h="pb"`) at its middle (t = ½ on the curve) instead of the centre dot. Dragging it (`D.t` `bend`, step "Bend line") writes `M a Q c b` with the curve passing through the pointer (`c = 2h − mid`); Shift keeps the point on the perpendicular through the chord's middle (symmetric), and within 3 px of the chord it goes back to `M a L b`. A `<line>` first becomes a `<path>` (`l2p`: same id and attributes, fill none). `seg()` reads such quadratic paths too (`QSEG`; the control point rides on the array as `.c`), and `setSeg(e,[a,b])` keeps the bend's proportion to the chord when the ends move (the curve's midpoint in chord coordinates), so end drags and connectors (`lnk`, `lkPv`) keep the curve; `setSeg(e,s,null)` writes a straight line. A single line is moved by dragging its stroke.
  - Wedge, elbow connector and brace (asked for by the user, Oct 2026; W in the rectangle group, E and { in the line group). `LNT` lists the line-like tools (snapping, preview). The wedge (`WDG`) is a `<polygon>`: thin end at the drag's start, flat along the box's bottom, tall at its end; with no fill set it is filled with the stroke colour (black) and no stroke, so it comes out solid. `SHP.brace(a,b,mm)` is a path of quadratic corners along a→b, depth 15 % of the length up to 2.5 mm, the point on the left of the drag direction (left to right: up; top to bottom: right); Shift keeps 45° steps; round caps and joins; it is not a connector (no attachment). The elbow is an absolute `M` plus 2–6 alternating `H`/`V` legs with an arrowhead (`hd`), routed by `rte(S,E,A,B,g,hn)` (rewritten Oct 2026 after the user reported elbow bugs: ends entering along an edge, lines crossing their own boxes, legs doubling back through the start object): an end attached to an object's edge gets an outward direction and the object's box (`elS`, from the attachment's u/v through `lkP`, so transforms and rotations count; corners, centres and free ends get none). The router tries 1- to 4-bend routes through candidate coordinates (the midpoint or the hint, 3 mm stubs, each box ± 3 mm, the middle of the gap between the boxes), rejects any that doubles back, leaves or enters against a direction, or crosses a box's interior, and keeps the shortest, counting 3 mm per bend; a free end faces the other end along its axis, two free ends keep the old Z along the longer axis. `elR` turns the points into `{h,v}`, `elD` writes them and `ePts` reads them back; a straight route keeps a zero-length middle leg so both markers stay oriented. `seg()` reads these paths (`ESEG`, relative `m`/`h`/`v` too, as Inkscape saves them; `r.e={h,v}`). `setSeg(e,s,c,dd)` re-routes an elbow whenever its ends move (`dd` overrides an end's attachment: the snapped object during an end drag, the drag matrix `M` in `lkPv`), keeping a 3-leg route's middle at its proportion between the ends when it lies between them; the end drag and `lkPv` put the original `d` back before each re-route so that hint doesn't drift. Drawing and its preview use the same router (`spO` turns a snap into `{t,u,v}`, `uvOf` gives u/v). The diamond sits on the middle leg (`v.length>>1`) and drags it (`D.t` `elb`, step Move elbow), adding a last leg when that leg ended at the end point. Headless: ~0.04 ms per route, ~0.2 ms when it goes around a box. While a drawing tool is chosen, presses ignore the selection's handles (`down`), so a new connector can start where the selected one does; and snapping adds 0.6 px to the distance of points on line-like objects (`T.l`), so a point shared by an object and a connector's end goes to the object.
  - Every selection gets a centre dot (`data-h="mv"`, hidden while editing text); dragging it is a plain move, so thin lines and arrows, whose end handles sit under the arrowhead, can be moved. A click on it without a drag acts like a click on the object beneath, and with Ctrl/⌘/Shift it is ignored, so Ctrl+click on the centre still selects the whole group. A double-click with a modifier doesn't enter point editing.
  - A Shift+click (no drag) on a box or rotate handle toggles the object under it (`tog`, shared with Shift+click), since handles can cover a selected object's centre.
  - Handles sit outside selections under 24 px on screen, so small points can be dragged. `curParent()` skips clipped groups so new shapes and pastes are not clipped away.
- Lock (`lock`/`unlock`, Ctrl+2 / Ctrl+Alt+2, Select menu and context menu): writes Inkscape's `sodipodi:insensitive` (namespace declared with `xns`), so Inkscape keeps the lock. A namespace-attribute CSS block makes locked nodes `pointer-events:none` (clicks pass through to what is below); `lkd(e)` (ancestors up to root, ignoring layers) additionally filters them out of selection, Select all, All text, Same fill/stroke and the marker-panel buttons. `cands(c,lk)` skips locked candidates (so Ctrl+A and box select pass over them) unless called with `lk` — snap targets, Fit page and the import check include locked objects. `unlock` strips the attribute from everything, selects the unlocked non-layers and reports locked layers separately; locking a layer only writes the attribute for Inkscape.
- Scrollbars (`#mSx`/`#mSy`, `bars()` called from `place()`, geometry in `sbg(h)`): overlay thumbs on the canvas's bottom and right edges, grey (`--sbt`/`--sbh`) over a rounded backdrop (`--sbk`) that appears on hover, visible in both themes. They idle at 55 % opacity and wake to full (`#mView.sbOn`, set for 1.2 s by `sbWake()`) whenever the view moves or the pointer comes within 28 px of an edge. The range is the page ± 20 px (the margin `fit()` leaves) joined with the visible area, so they hide at fit or whenever the page is inside the window; thumbs are at least 32 px. Dragging a thumb pans one axis with the range frozen in `sbR`; pressing the track centres the thumb there and keeps dragging. Wheel panning stays unbounded; the range then grows to include the view.
- Rulers (`rulers()`, canvases `#mRx`/`#mRy`, `RW` = 20 px): drawn with a swapped transform for the left ruler, `--bar` with the page span in `--btn`, tiers of ticks (major with `--h4` labels, half, minor at half alpha) on a 1-2-5 step of at least 50 px, the selection span in translucent blue, the pointer in orange, and a corner showing "mm". Shown unless the user turned them off; `fit()` leaves room for them.
- Guides (`gl`, items `{h,v}`: `h` 1 = vertical line at x = `v`, 0 = horizontal at y, in user units): the ruler canvases take pointer events and stop propagation, so `down` never sees them. A click pins a guide (`gv` rounds to the largest power of ten under a screen pixel), a click within 5 px of a mark (`gAt`) removes it, dragging a mark moves it, and dragging from a ruler into the page gives the other orientation (`gp` is the in-progress guide, `gq` the hover, shown as a dashed preview or a red "remove" mark). `hud()` draws them under everything else; `snapSet` adds them as move snap targets, and `gsn(u,e)` snaps points to them within 5 px (Ctrl/⌘ off, not with Shift) while drawing with the shape and line tools, dragging a line end (`pt`) or a point (`anc`, so the anchor itself lands on the guide); the snapped guide shows as the orange `D.g` line. View state only: not exported, not undoable, cleared by `load`; View › Clear guides (`gclr`), and while any exist a "Clear N guides" pill (`#mGc`, kept in step by `bar()`) sits at the canvas's top left for one-click clearing. Look: dashed rose `GC` (the user found the first sky blue ugly), solid `GH` when a click would remove one, a faint dashed preview under the pointer.
- Auto-scroll at the edge: any move/resize/box-select drag (`edgeTick`, a rAF loop started from `move`) pans the view by up to 24 px per frame once the pointer is within 24 px of the canvas edge, shifting `D.p` along so the drag keeps working.
- Drag preview ("ghost"): selected nodes move into `svg#mGhost` inside `div#mGW`. The CSS transform goes on the div, not the svg, so text doesn't re-layout.
- Snapping: when a move drag starts, `snapSet()` stores the selection box in `D.s0` and the snap targets in `D.sn`. Targets are the page's edges and centre, plus, when there are fewer than 500 of them, the bbox edges and centres of the other objects in `ctx` (`cands` with `lk`, so locked objects snap too; root when `ctx` is a layer). `move` snaps the box's edges or centre within 5 px on screen and keeps the matched lines in `D.g`, which `hud()` draws in orange. Ctrl/⌘ turns snapping off. Shift keeps the move to 45° steps, and only the free axis snaps. Line, arrow and inhibition ends also snap to objects (asked for by the user, Oct 2026), both while drawing (start at pointerdown, end on move) and when dragging a selected line's end (`pt`, excluding that line): `snapT(X)` collects, once per drag, from the leaves in view (`klea(root)`, `fb` for the in-view test) anchors (pmodel points, line ends), midpoints of straight segments, centres of closed shapes (from their anchors, so exact even when rotated), text/image box corners, midpoints and centres (from `fb`, ~0.001 units off), and every outline segment (`outl`); it gives up — no object snapping for that view, remembered in `SO` until the pan, zoom or file changes — past 4000 objects in view or 80 ms (100k-element svglite files at fit: off; 20k texts zoomed in: on). `lsn(u,e,T)` takes the nearest point within 6 px (`osn`), else a guide (`gsn`), else the nearest point on an outline within 6 px; Ctrl/⌘ turns it off, Shift (45°) skips it. `hud` marks `D.sp` with an orange ring (point) or diamond (outline), and the status line says "On an anchor / a midpoint / a centre / an edge" ("· on …" after the length while dragging an end). Connectors (asked for by the user, Oct 2026): an end that snaps to an object (the `e` that `osn` returns with each point) is attached — `lkSet(c,i,sp)` writes `data-sg-from` / `data-sg-to` = `url(#id) u v` on the line, `u`/`v` being the point's place in the target's own `getBBox()` (so it follows moves, scales, rotations and text edits); a target without an id gets one. Drawing (`create(t,a,b,L)` with `D.sp0`/`D.sp`) attaches both ends; dragging an end (`pt`) re-attaches or detaches that end. `lnk()` runs at the start of every `commit()`, moving each attached end of a two-point line (`seg`/`setSeg`) to `lkP(t,u,v)` when it is off by over 5e-6, so the object's change and the arrow's are one undo step; `lkAll()` caches the connector list per `svn` and `lkV` (bumped by `lkSet`, `lkDet` and `undo`), so files without connectors pay nothing. While a move/scale/rotate drag runs, `lkPre` (before `ghostOn`) notes the attached ends of unselected connectors whose objects are selected and `lkPv(M)` moves them quietly each frame; `lkRs` puts the exact original attributes back before the real commit (in `up` and `esc`). `applyM` calls `lkDet(els)`: a connector moved without its object (judged against `els` plus the selection, since Align moves one object at a time) loses that end's attachment. Copies: `paste` now renames ids across all pasted items with one map (`reid(n,M)`, then one `relink`), so an arrow pasted with its objects attaches to the copies, and `lkCut` drops attachments to anything not pasted (also in `doImport`, after `pfx`). A deleted target leaves the attribute dangling (undo restores both). Attached ends show as filled blue handles. The attributes are svguest's own; Inkscape's connector attributes were not used, since Inkscape would re-route such lines centre to centre.
- Style copy: `styCopy(l)`/`styPaste(a)` (used by the eyedropper; no menu items or keys, Ctrl+Shift+V is Paste in place) keep `sty`: the `PS` paint values, the stroke width in pt (`ptw`), the dashes as multiples of the width, and for text its family, weight, style and size. Paste sets them on the leaves of selected groups (`klea`), so widths and sizes keep their pt. `alike(p)` (Select menu, actions `sf`/`ss`) selects every text, or every shape, whose computed fill or stroke matches the first selected leaf (`lf0`).
- Eyedropper (`drop` tool, in `down()`): a click picks the clicked object's style into `sty` and applies it to the selection, unless the click is inside the selection. Alt+click applies `sty` to the clicked object.
- Fill/stroke swatches (`#mFS` in the tool bar: `#mFF`/`#mSF` labels over transparent colour inputs `#mFc`/`#mSc`): `panel()` paints them with `fsw()`. They colour the selection through `styleSet`, or set `pen`, the fill and stroke `create()` gives new rectangles and ellipses, when nothing is selected. Lines and arrows keep fill none, and fall back to black when `pen.stroke` is none. `swapFS()` (Shift+X, action `swap`) swaps the computed fill/stroke and their opacities on every leaf, or swaps `pen`; `pnt()` writes rgb as hex and paint servers as `url(#id)`. Colours preview live while the picker is open (asked for by the user, Oct 2026): for the side panel's Fill, Stroke and text Color and the two swatches, an `input` event (`cpIn`) marks the leaves `styleSet` would change (`sLv`, the same leaf rule; for text Color `selTexts()`) with a quiet `data-mcp` attribute and sets one `!important` rule in the page's own `<style>` (`CPS`/`CPR`, `#mStage [data-mcp]` and its tspans), so an update is one rule change however many objects are selected. `cpEnd` removes markers and rule (quietly) on `change` (in the capture phase, before the real handlers apply and commit as before, so the result and its single undo step are unchanged), on pointerdown elsewhere, on Esc, when the value returns to where it started (`t._v0`, taken on pointerdown/focusin, which also covers a cancelled picker) and in `svgText`. No preview while editing text in place, or with nothing selected (then only the swatch follows). Headless, 100k selected: ~0.7 s to start, then ~0.5–1 s per update; small selections are instant.
- Class styling (svglite): a `<style>` scopes to a class-carrying group. `ungroup()` and pasting onto another canvas snapshot the computed `KP` values (fill, stroke, linecap, linejoin, miterlimit) of the leaves (`klea`/`kps`/`kpr`) and write back inline only what would change; `styleSet` on a group skips leaves whose fill/stroke computes to none. `klea(g)` and `leaf(g,f,cap)` walk leaves with a TreeWalker (`twalk`) that never enters defs/clipPath/mask/marker/pattern/symbol; `setSts(e,kv)` writes several style properties at once into the style attribute (order-preserving) and removes their presentation attributes.
- Text editing: `edit()` / `finish()` use a contenteditable `.ed` overlay. As in Illustrator, Esc finishes (`finish(true)`; Ctrl+Z undoes it) and switches to the Select tool and Enter starts a new line; there is no cancel key. Ctrl+Shift+= / Ctrl+Alt+Shift+= superscript and subscript while editing. The same editor also runs in the Text panel (asked for by the user, Oct 2026, because editing on the canvas sometimes misbehaved; formatting kept): `#mTx` at the top of the Text section shows the one selected text (or the only text in a selected group) through `edSrc`/`edFill` (the same `mirror` as in place), rebuilt by `panel()` only when the text or `dv` changes; focusing it calls `edit(t,null,,1)` (`ed.sd`), which keeps the box's DOM and caret instead of placing an overlay. While typing, the original stays hidden as in place and a quiet clone (`ed.pv`, ids dropped, `pointer-events=none`) shows the result: `edPv` (once per frame via `edPvQ`, also after `restyle` and on `panel()`) inserts a fresh clone of `t` first and then applies `setLines(clone, run at path ed.ip, …, edMap(ks, lines))` and `noTL` — layout needs the clone in the document, or every line lands at y = 0 — and puts back `xmlns:sodipodi` if `setLines` added it. `finish` removes the clone and writes the real text exactly as for in-place editing (one "Edit text" step; unchanged text stays byte-identical). Multi-line texts written as one positioned tspan per line (Illustrator: `<tspan x y>` children, one x and one y each, y rising, nothing but whitespace between; seen in the user's main1_260509.svg, Oct 2026, where double-clicking one line edited only that line while the others vanished) count as lines too (`edLn`, used by `edSrc` and `setLines`; `lnKids` stays Inkscape's `sodipodi:role="line"` only, for `relines` and `tryWrap`): the editor and the box show every line, each line keeps its own x and y, a deleted line loses its tspan, and a new line takes the previous line's x plus the average spacing of the existing lines. Same-line runs (equal y, e.g. kerning) are not lines. When editing only a run inside a text in place, only that run is hidden (`ed.hv`), not the whole text. - In TBtools (JxBrowser, macOS built-in Pinyin), Chinese punctuation typed into the SVG Chat box did nothing (Chromium types it fine). Fixed in the plugin's `PluginInject` (see the skill's "Chinese punctuation on macOS"), tested only with mocks; confirm in TBtools, including the T tool's editor.
- The ChatGPT plan bridge (TBtools): the user tried the plugin with the proxy fixes in TBtools and reported it works (Oct 2026). Before those fixes, a second sign-in after signing out failed with "Unable to tunnel through proxy. Proxy returns \"HTTP/1.1 403 Error\"" and `http://127.0.0.1:53170` in the Proxy field — the bridge's own refusal line, so that port was most likely a bridge (cause unconfirmed; the bridge now names itself, falls back to the system proxy and tests the field). A later report (TBtools-II 2.561, plugin opened right after installing) failed at the first request with `NoClassDefFoundError: Plugin/Siwc$Net`: TBtools had closed the plugin's class loader; `PluginInject` now preloads every class in its jar (see the skill). Which parts they exercised wasn't said: image input, `reasoning.summary` and `xhigh` on the plan route, and the proxy fallback are confirmed only against a mock. The skill's `PluginInject.java` now includes the `OpenFileCallback` hook, recovered from the previously shipped jar's bytecode, so the plugin can be rebuilt again (Oct 2026).
- Ctrl/⌘K, Ctrl+Shift+L and F7 are untested in Safari, Firefox and TBtools' JxBrowser (the host may take them first). Guides are not saved in the SVG (Inkscape's `sodipodi:guide` was not attempted: its coordinates could not be checked without Inkscape).
- Open recent and autosave were tested only in headless Chromium (reload, closing the tab, restarting the browser, 10-entry cap). Like chats, the copies are per browser and origin; IndexedDB and CompressionStream in Safari (private windows, file://) and TBtools' JxBrowser are untested, and without IndexedDB the submenu says "Not available in this browser".
- Chats are kept per browser and origin (a downloaded copy has its own). The submenu hover bridge and the Kept in this browser zip were tested only in headless Chromium (the zips open in Python's zipfile). Auto-save to a folder was tested only with the picker mocked by an origin-private folder (writes, rewrites, reload, paused/resume/refuse, off); the real picker, Chrome's permission prompt (and its "allow on every visit") and TBtools' JxBrowser (Chromium, but its folder dialog may need a host callback) are untested. Their persistence in Safari (private windows, file://) and TBtools' JxBrowser is untested; switching chats is refused while a reply runs.
- TIFF is not supported: only Safari decodes it, and an embedded TIFF wouldn't show in most SVG viewers. A built-in decoder that converts to PNG on import was offered and declined by the user (Oct 2026). A TIFF dropped on the canvas currently goes to SVG Chat as an unreadable attachment ("can't read this type").
- Connectors: only two-point lines, `M … L …`/`M … Q …` paths and elbows (`M` plus 2–6 alternating H/V legs) follow; polylines and other curves can snap but don't attach. A two-segment H/V path from another app now counts as an elbow (end handles instead of the box). Wedge, brace and elbow were tested only in headless Chromium. Other apps keep the line where it is (the attributes are svguest's own).
- Pasting a screenshot in TBtools on macOS did nothing (reported Oct 2026); the plugin now fetches the clipboard image through its bridge (see the ChatGPT plan bullet). Tested only on Linux/Xvfb with a page forced to report a Mac; confirm in TBtools.
- Pasting SVG text trusts `text/plain` that starts with `<svg`/`<?xml` and differs from what this page last wrote; other clipboard flavours (an SVG wrapped in `text/html`, for instance) are ignored.
