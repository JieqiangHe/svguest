# svguest

A lightweight in-browser SVG editor for touching up ggplot2/svglite figures (often re-saved by Inkscape). Live at https://jieqianghe.github.io/svguest/ (GitHub Pages serves the `release` branch, updated only when a version is released): the address opens the cover page `index.html`, and Start editing (or Enter) opens the editor, `app.html`, in the same tab (Oct 2026, at the user's request). Renamed from minisvg in Oct 2026; until 22 Nov 2026 a separate `minisvg` repo serves a redirect page at the old address (jieqianghe.github.io/minisvg/ → /svguest/, keeping query and hash). Versions before the rename used the prefix `msb`; svguest starts fresh and carries none of it over (settings, Open recent, chats, `data-msb-*` connectors, `…Msb` markers, which now show as Custom): the user's choice, Oct 2026, so don't add migration code. The redirect repo holds only `index.html`, `404.html` (both `location.replace` to `/svguest/` with query and hash, meta refresh without JS) and a README. A Pages deploy that collides with one in progress fails; its re-run can hang in queued (neither cancellable nor re-runnable), and the next push deploys. Since v1.0.0 (21 Oct 2026) Pages deploys from the `release` branch (`/ (root)`), so the site changes only when a version is released (the `jh-svguest-release` skill: version in `app.html` (head comment, `#mBrand` title) and `index.html` (head comment, footer), commit to `main`, tag, `git push origin main:release`, `gh release create`); the svguest.online mirror (EdgeOne Pages) follows `release` too. Never delete `release` (it is both sites' source; the user deleted it once while cleaning up branches on 21 Oct 2026 and it was recreated at the v1.0.0 commit); other branches such as `claude/…` may be deleted. Before that it deployed from `main`, the user's choice: a GitHub Actions workflow deploy (a script check before publishing, Run workflow to redeploy) was tried in Oct 2026 and worked, but they went back to the branch; don't switch without asking. Changing the source needs no Unpublish site (that takes the site offline until the next deploy): pick the source, then the branch and folder, then Save.

- What a name means is written where it is defined in app.html (the contents list after `'use strict'` gives the sections); the notes here keep what the code doesn't say: history, measurements, the user's decisions.
- Zoom (Oct 2026): `Z` is set only by Fit and by Open recent's view (`vwSet`); every zoom changes `k` alone (`#mStage`'s CSS scale), and nothing folds `k` back into `Z` any more: that 250 ms settle restyled every element and re-laid out every text (~0.9 s at 100k elements, ~0.4 s with 20k texts) to change nothing on screen, and the drawing paints just as sharp under the CSS scale (checked against the old rendering: 15 anti-aliased pixels differ). `size()` sets `#mStage`'s own width and height; its four children (`#mPage,#mGrid,#mGW,#mStage>svg`, named so no universal rule is tested against every element of the drawing) are 100 %. Never put an inherited custom property on `#mStage` or above the drawing: changing one restyles every element in it (the old `--w`/`--h` cost 880 ms at 100k). `place()` gives `#mPage` and `#mGrid` alone a `--k`, so the page outline and shadow and the grid's lines (non-scaling strokes ignore CSS transforms) stay 1 px; `grid()` spaces lines by `Z*k` and is redrawn 250 ms after a zoom.
- Undo (mechanics: 04 Undo in app.html): `revert` names a re-added namespaced attribute through `PX`, which includes the xmlns namespace: without it, redoing a step in which `xns` declared a namespace on the root (Lock, a second text line, Place image, Rename, in files without that declaration) threw halfway and lost the step (fixed Oct 2026). Undo restores values, not attribute order: a presentation attribute that was removed and put back moves to the end. A step that moves over 5000 nodes and over a third of the document (`mvs`) is replayed with the root detached (`dtch`): moves inside the live document cost ~15 µs each, and `revert` needs no ids or computed styles (Undo of Ungroup all at 100k elements 3.6 → 1.1 s, Redo 3.0 → 1.7 s; the result is identical). Multi-commit sequences (Alt+drag copy, transform again, pasteZ, ungroupAll, held arrow keys, AI patch/import) wrap their work in `once(f,j)`.
  - Step names: every step carries `n`, set from `why` (cleared by each `commit`) or, failing that, `guess(records)` (Edit text, Rearrange, Add, Delete, Transform, Edit shape, Page size, Lock, Style, Change). `why` comes from the button's name (`bName`, via the body click handler), the key's action (`AN`, action function → name, filled at startup), the side-panel field, `up()` per drag type (Move, Scale, Rotate, Draw rectangle…), `nudge`, `paste`, `fsz`, `finish`. Merged steps keep the first name. `bar()` writes them into Edit › Undo/Redo ("Undo Nudge"); `undo()` reports "Undo: Nudge". Edit › History (`#mHi` submenu, `hiL()` rebuilds `#mHm` on hover) lists up to 12 redo steps (`fu`, dimmed), the current step (ticked), 25 undo steps and Start; a click undoes/redoes that many steps quietly (`undo(r,1)`) and reports "Went back N steps". `svd` is the undo top at the last save/load (`load` sets null), so undoing back to it clears `dirty`; `dv` counts document versions (for caches such as `hcp`).
- Matrices (see 02 Geometry): `ctm` skips ancestors without a transform because a `preMultiplySelf` with an identity cost 7–12× the rest of `ctm`, which sits under every bbox, hover and selection (Oct 2026); `bbox`/`tsize` skip the multiply for untransformed elements. `order` switches to a TreeWalker index map at 64 elements because compareDocumentPosition sorting gets slow on big files.
- Untouched elements must serialise byte-identical.
- Bounding boxes (see 02 Geometry): groups with more than 2000 descendants (`BIG`) fall back to the loose box for speed.
- Selection: handles live in `H`. Locked elements (see Lock below) are filtered out of every selection.
  - Click selects the part under the pointer (`grab`); Ctrl/⌘+click selects its top-level object (`pick`). `ctx` is the group of the selection; Esc climbs it, an empty click resets it to root, and `refresh()` resets it to root when it has left the document (Ungroup used to leave it on the removed group: Esc then threw and Ctrl+A selected nothing). Alt+click without a drag (`selBelow`) cycles through the objects stacked under the pointer (uses `elementsFromPoint` via `thru`), reporting "object 2 of 4".
  - Hover: with no drag under the Select, Eyedropper or Text tool, `hoverAt`/`hovCalc` outline in blue (`hud`) the object the pointer is over — its true outline (`outl(e)`: line endpoints, or a path's anchors with C/Q/A sampled at 8 points each via `arcPts`) as polylines, falling back to its bbox for shapes it can't read. Throttled to one calc per animation frame, or a 90 ms timeout when `hit()` last took over 12 ms; hidden over handles, scrollbars, rulers, the Layers button, the text editor or an already-selected object, and Ctrl held switches to the top-level object. Over a Layers row, `hovCalc` takes that row's element instead, so the canvas outline follows the list (and `lyHv` marks the row of the object hovered on the canvas).
  - Right-click opens the context menu (`cmenu`, `#mCM`, entries in `CM`): Cut/Copy/Paste here/Paste in place/Delete, Crop image and Remove crop (only when the selection is one `<image>`; the second only when it carries our crop, `cropK`), Group/Ungroup, z-order, Select the object below, Same fill/stroke, Lock/Unlock all. `cmE` remembers the event so Paste here pastes at the pointer; Ctrl+click (which also fires contextmenu on a Mac) is ignored, so Ctrl+click selection keeps working; the menu closes on outside pointerdown, click, blur, resize or Esc (which doesn't deselect). Actions `cut`, `below`, `pasteHere`, `cropI` (the crop tool, which opens the crop box on the selected photo) and `uncrop` (`cropR` with the whole photo) exist only for the menu.
  - `hit(e)` (see 14 Hit testing) tests one point at a time: elementsFromPoint costs ~35 ms per call on a 150k-element file. The search for a thin line or mark above stops after 40 ms.
  - A click on the page background starts a box select, not a move: `bd(t)` recognises a filled rect that is first among its siblings, covers at least a quarter of the page and fully contains another leaf (`down` starts a `band`, and a click without a drag selects the rect).
  - Box select `boxed(c,R,tch)`: whole groups that fit are taken, else it recurses into them; children of a group with over 2000 (`BIG`) children are measured with getBoundingClientRect, and so is every other leaf without a clip-path (`fb(e,V)`: the native box mapped back to user units; groups and clipped elements still go through `bbox`). `refresh()` uses `fb` too when over 300 objects are selected. `lbox` finds a group's clipped child through `hcp(e)`, cached per `dv`. Ctrl/⌘ during the drag maps each hit to its top-level object (`pick`) before deduping. Alt+drag is touch select (`tch`): anything the box intersects is taken too; View › Box select touches (`opts.touch`, `sgTouch`) is on by default, as in Illustrator (the user's choice, Oct 2026, knowing that in a ggplot panel a touching box also grabs every gridline it crosses): a plain drag touches and Alt+drag encloses; turned off, the two swap (`tch` = Alt XOR the option, read when the drag starts; the status line says "N objects touch the box" or "N objects in the box"). Touching works via `touches(e,R)` (a point in `inR`, or an outline segment crossing the rect with the slab test `sr`); always against the drag box itself — `fb` boxes are ~0.001 units off, so testing against the box clipped to them missed every vertical or horizontal line). After 60 ms of dragging, `bandPrev` previews the would-be selection — blue boxes (`D.pv` drawn by `hud`) plus a count in the status line — and switches itself off (permanently for that drag) when measuring takes over 60 ms on a large file.
  - Point editing (`ped`, like Illustrator's direct selection): a click without a drag on a corner handle, or a double-click on a shape, shows the shape's anchors as hollow squares (`data-h=a<i>`) in place of the box handles. Dragging one moves only that anchor plus the curve handles attached to it (`moveA`); Shift gives 45° steps. Esc, a new selection or a click outside ends it. `pmodel(e)` reads rect (rounded ones as arcs), circle, ellipse, polygon/polyline and path (`pparse`: absolute M/L/C/Q/A/Z, with H/V/S/T folded in; null for paths it can't read or over 2000 segments). Results are cached per element in `PMC`, keyed on its `d`/`points` (a 100k-point path was re-parsed on every hover and every `hud()` while point editing, 40 ms each), so callers must treat the model as read-only (the anchor drag copies `o` before `moveA`). A closed subpath's last point that repeats its start is linked to it (`anchorsOf`). On the first real drag a rect, circle or ellipse becomes a `<path>` (`toPath`, keeping id and attributes; `kps`/`kpr` keep class-styled paint). The skew mode tried before was dropped.
  - Bending a line (asked for by the user, Oct 2026): one selected two-point line or arrow shows a diamond (`data-h="pb"`) at its middle (t = ½ on the curve) instead of the centre dot. Dragging it (`D.t` `bend`, step "Bend line") writes `M a Q c b` with the curve passing through the pointer (`c = 2h − mid`); Shift keeps the point on the perpendicular through the chord's middle (symmetric), and within 3 px of the chord it goes back to `M a L b`. A `<line>` first becomes a `<path>` (`l2p`: same id and attributes, fill none). `seg()` reads such quadratic paths too (`QSEG`; the control point rides on the array as `.c`), and `setSeg(e,[a,b])` keeps the bend's proportion to the chord when the ends move (the curve's midpoint in chord coordinates), so end drags and connectors (`lnk`, `lkPv`) keep the curve; `setSeg(e,s,null)` writes a straight line. A single line is moved by dragging its stroke.
  - Wedge, elbow connector and brace (asked for by the user, Oct 2026; W in the rectangle group, E and { in the line group). `LNT` lists the line-like tools (snapping, preview). The wedge (`WDG`) is a `<polygon>`: thin end at the drag's start, flat along the box's bottom, tall at its end; with no fill set it is filled with the stroke colour (black) and no stroke, so it comes out solid. `SHP.brace(a,b,mm)` is a path of quadratic corners along a→b, depth 15 % of the length up to 2.5 mm, the point on the left of the drag direction (left to right: up; top to bottom: right); Shift keeps 45° steps; round caps and joins; it is not a connector (no attachment). The elbow is an absolute `M` plus 2–6 alternating `H`/`V` legs with an arrowhead (`hd`), routed by `rte(S,E,A,B,g,hn)` (rewritten Oct 2026 after the user reported elbow bugs: ends entering along an edge, lines crossing their own boxes, legs doubling back through the start object): an end attached to an object's edge gets an outward direction and the object's box (`elS`, from the attachment's u/v through `lkP`, so transforms and rotations count; corners, centres and free ends get none). The router tries 1- to 4-bend routes through candidate coordinates (the midpoint or the hint, 3 mm stubs, each box ± 3 mm, the middle of the gap between the boxes), rejects any that doubles back, leaves or enters against a direction, or crosses a box's interior, and keeps the shortest, counting 3 mm per bend; a free end faces the other end along its axis, two free ends keep the old Z along the longer axis. `elR` turns the points into `{h,v}`, `elD` writes them and `ePts` reads them back; a straight route keeps a zero-length middle leg so both markers stay oriented. `seg()` reads these paths (`ESEG`, relative `m`/`h`/`v` too, as Inkscape saves them; `r.e={h,v}`). `setSeg(e,s,c,dd)` re-routes an elbow whenever its ends move (`dd` overrides an end's attachment: the snapped object during an end drag, the drag matrix `M` in `lkPv`), keeping a 3-leg route's middle at its proportion between the ends when it lies between them; the end drag and `lkPv` put the original `d` back before each re-route so that hint doesn't drift. Drawing and its preview use the same router (`spO` turns a snap into `{t,u,v}`, `uvOf` gives u/v). The diamond sits on the middle leg (`v.length>>1`) and drags it (`D.t` `elb`, step Move elbow), adding a last leg when that leg ended at the end point. Headless: ~0.04 ms per route, ~0.2 ms when it goes around a box. While a drawing tool or the Text tool is chosen, presses ignore the selection's handles (`down`), so a new connector can start where the selected one does and a Text-tool click on a selected text edits it (its centre dot used to start a move); and snapping adds 0.6 px to the distance of points on line-like objects (`T.l`), so a point shared by an object and a connector's end goes to the object.
  - Every selection gets a centre dot (`data-h="mv"`, hidden while editing text); dragging it is a plain move, so thin lines and arrows, whose end handles sit under the arrowhead, can be moved. A click on it without a drag acts like a click on the object beneath, and with Ctrl/⌘/Shift it is ignored, so Ctrl+click on the centre still selects the whole group. When that object is already the whole selection, `up` doesn't call `setSel`: the redraw replaced the dot under the second click and Chromium dropped the double-click, so double-clicking a text or shape at its centre did nothing (fixed Oct 2026). A double-click with a modifier doesn't enter point editing.
  - A Shift+click (no drag) on a box or rotate handle toggles the object under it (`tog`, shared with Shift+click), since handles can cover a selected object's centre.
  - Handles sit outside selections under 24 px on screen, so small points can be dragged. `curParent()` skips clipped groups so new shapes and pastes are not clipped away.
- Lock (`lock`/`unlock`, Ctrl+2 / Ctrl+Alt+2, Select menu and context menu): writes Inkscape's `sodipodi:insensitive` (namespace declared with `xns`), so Inkscape keeps the lock. A namespace-attribute CSS block makes locked nodes `pointer-events:none` (clicks pass through to what is below); `lkd(e)` (ancestors up to root, ignoring layers) additionally filters them out of selection, Select all, All text, Same fill/stroke and the marker-panel buttons. `cands(c,lk)` skips locked candidates (so Ctrl+A and box select pass over them) unless called with `lk` — snap targets, Fit page and the import check include locked objects. `unlock` strips the attribute from everything, selects the unlocked non-layers and reports locked layers separately; locking a layer only writes the attribute for Inkscape.
- Scrollbars (`#mSx`/`#mSy`, `bars()` called from `place()`, geometry in `sbg(h)`): overlay thumbs on the canvas's bottom and right edges, grey (`--sbt`/`--sbh`) over a rounded backdrop (`--sbk`) that appears on hover, visible in both themes. They idle at 55 % opacity and wake to full (`#mView.sbOn`, set for 1.2 s by `sbWake()`) whenever the view moves or the pointer comes within 28 px of an edge. The range is the page ± 20 px (the margin `fit()` leaves) joined with the visible area, so they hide at fit or whenever the page is inside the window; thumbs are at least 32 px. Dragging a thumb pans one axis with the range frozen in `sbR`; pressing the track centres the thumb there and keeps dragging. Wheel panning stays unbounded; the range then grows to include the view. Back to page (asked for by the user, Oct 2026): `#mBk`, a pill at the canvas's bottom centre, shows (`bkB()` from `place()`) when less than half of the smaller of the page and the view is visible; a click (`ctrPg`) centres the page at the current zoom (Ctrl+0 still fits).
- Rulers (`rulers()`, canvases `#mRx`/`#mRy`, `RW` = 20 px): drawn with a swapped transform for the left ruler, `--bar` with the page span in `--btn`, tiers of ticks (major with `--h4` labels, half, minor at half alpha) on a 1-2-5 step of at least 50 px, the selection span in translucent blue, the pointer in orange, and a corner showing "mm". Shown unless the user turned them off; `fit()` leaves room for them.
- Guides (`gl`, items `{h,v}`: `h` 1 = vertical line at x = `v`, 0 = horizontal at y, in user units): the ruler canvases take pointer events and stop propagation, so `down` never sees them. A click pins a guide (`gv` rounds to the largest power of ten under a screen pixel), a click within 5 px of a mark (`gAt`) removes it, dragging a mark moves it, and dragging from a ruler into the page gives the other orientation (`gp` is the in-progress guide, `gq` the hover, shown as a dashed preview or a red "remove" mark). `hud()` draws them under everything else; `snapSet` adds them as move snap targets, and `gsn(u,e)` snaps points to them within 5 px (Ctrl/⌘ off, not with Shift) while drawing with the shape and line tools, dragging a line end (`pt`) or a point (`anc`, so the anchor itself lands on the guide); the snapped guide shows as the orange `D.g` line. View state only: not exported, not undoable, cleared by `load`; View › Clear guides (`gclr`), and while any exist a "Clear N guides" pill (`#mGc`, kept in step by `bar()`) sits at the canvas's top left for one-click clearing. Look: dashed rose `GC` (the user found the first sky blue ugly), solid `GH` when a click would remove one, a faint dashed preview under the pointer.
- Auto-scroll at the edge: any move/resize/box-select drag (`edgeTick`, a rAF loop started from `move`) pans the view by up to 24 px per frame once the pointer is within 24 px of the canvas edge, shifting `D.p` along so the drag keeps working.
- Drag preview ("ghost"): selected nodes move into `svg#mGhost` inside `div#mGW`. The CSS transform goes on the div, not the svg, so text doesn't re-layout. `#mGW` gets `will-change:transform` only during a drag (class `dr`, set in `ghostOn`, dropped in `ghostOff`) and never in Safari (`GWL`): the user saw the drawing go blurry when zoomed in (27 Oct 2026). Not verified in Safari itself (no WebKit here); never put `will-change` or another compositing trigger inside `#mStage` permanently.
- Snapping: when a move drag starts, `snapSet()` stores the selection box in `D.s0` and the snap targets in `D.sn`. Targets are the page's edges and centre, plus, when there are fewer than 500 of them, the bbox edges and centres of the other objects in `ctx` (`cands` with `lk`, so locked objects snap too; root when `ctx` is a layer). `move` snaps the box's edges or centre within 5 px on screen and keeps the matched lines in `D.g`, which `hud()` draws in orange. Ctrl/⌘ turns snapping off. Shift keeps the move to 45° steps, and only the free axis snaps. Line, arrow and inhibition ends also snap to objects (asked for by the user, Oct 2026), both while drawing (start at pointerdown, end on move) and when dragging a selected line's end (`pt`, excluding that line): `snapT(X)` collects, once per drag, from the leaves in view (`klea(root)`, `fb` for the in-view test) anchors (pmodel points, line ends), midpoints of straight segments, centres of closed shapes (from their anchors, so exact even when rotated), text/image box corners, midpoints and centres (from `fb`, ~0.001 units off), and every outline segment (`outl`); it gives up — no object snapping for that view, remembered in `SO` until the pan, zoom or file changes — past 4000 objects in view or 80 ms (100k-element svglite files at fit: off; 20k texts zoomed in: on). `lsn(u,e,T)` takes the nearest point within 6 px (`osn`), else a guide (`gsn`), else the nearest point on an outline within 6 px; Ctrl/⌘ turns it off, Shift (45°) skips it. `hud` marks `D.sp` with an orange ring (point) or diamond (outline), and the status line says "On an anchor / a midpoint / a centre / an edge" ("· on …" after the length while dragging an end). Connectors (asked for by the user, Oct 2026): an end that snaps to an object (the `e` that `osn` returns with each point) is attached — `lkSet(c,i,sp)` writes `data-sg-from` / `data-sg-to` = `url(#id) u v` on the line, `u`/`v` being the point's place in the target's own `getBBox()` (so it follows moves, scales, rotations and text edits); a target without an id gets one. Drawing (`create(t,a,b,L)` with `D.sp0`/`D.sp`) attaches both ends; dragging an end (`pt`) re-attaches or detaches that end. `lnk()` runs at the start of every `commit()`, moving each attached end of a two-point line (`seg`/`setSeg`) to `lkP(t,u,v)` when it is off by over 5e-6, so the object's change and the arrow's are one undo step; `lkAll()` caches the connector list per `svn` and `lkV` (bumped by `lkSet`, `lkDet` and `undo`), so files without connectors pay nothing. While a move/scale/rotate drag runs, `lkPre` (before `ghostOn`) notes the attached ends of unselected connectors whose objects are selected and `lkPv(M)` moves them quietly each frame; `lkRs` puts the exact original attributes back before the real commit (in `up` and `esc`). `applyM` calls `lkDet(els)`: a connector moved without its object (judged against `els` plus the selection, since Align moves one object at a time) loses that end's attachment. Copies: `paste` now renames ids across all pasted items with one map (`reid(n,M)`, then one `relink`), so an arrow pasted with its objects attaches to the copies, and `lkCut` drops attachments to anything not pasted (also in `doImport`, after `pfx`). A deleted target leaves the attribute dangling (undo restores both). Attached ends show as filled blue handles. - Style copy: `styCopy(l)`/`styPaste(a)` (used by the eyedropper; no menu items or keys, Ctrl+Shift+V is Paste in place) keep `sty`: the `PS` paint values, the stroke width in pt (`ptw`), the dashes as multiples of the width, and for text its family, weight, style and size. - Fill/stroke swatches (`#mFS` in the tool bar: `#mFF`/`#mSF` labels over transparent colour inputs `#mFc`/`#mSc`; restyled as a "soft dock" at the user's request, 16 Oct 2026: a 40 px rounded base (`--fsd`, hairline `--line`, faint shadow) holding the swatches (22 px, 10 px apart; the stroke is a hollow ring, `box-shadow:inset` in its colour, so the fill shows through when it is in front; none is white with a red slash kept inside the border) with Swap (`#mFX`) at the top right, and under a hairline Default (`#mFD`) | No colour (`#mFN`); for it the user agreed to widen the toolbar from 40 to 48 px (every `grid-template-columns` starts with 48px; tool buttons 36 px with 22 px icons at stroke 1.5, links 36 px; 34/20 looked small to the user, and 38–40 px buttons made the selected tool's chip nearly fill the bar), still about 4 px short of the brief's 6–8 px margins, 24–28 px swatches and 24 px targets, which need ~56 px. - Text editing: `edit()` / `finish()` use a contenteditable `.ed` overlay. As in Illustrator, Esc finishes (`finish(true)`; Ctrl+Z undoes it) and switches to the Select tool and Enter starts a new line; there is no cancel key. A double-click, or a Text-tool click on a text, puts the caret where the click was (`edit(…,P)`: `caretRangeFromPoint` on the overlay, else the end). It used to select all, so the first keystroke or Pinyin letter replaced the whole text, which the user reported from TBtools as the text vanishing when they started to edit (Oct 2026).
