# minisvg

A lightweight in-browser SVG editor for touching up ggplot2/svglite figures (often re-saved by Inkscape). Live at https://jieqianghe.github.io/minisvg/ (GitHub Pages serves `main`). The repo was renamed from `minisvgbench`.

## Repo rules

- The whole app is one file, `index.html` (~100 KB). The repo contains `index.html`, `README.md`, `LICENSE`, `minisvg.plugin`, `.claude/` (the TBtools plugin skill), `.gitignore` and `CLAUDE.md`; only `.DS_Store` is gitignored. Do not add test files, build files or other folders.
- Plain JavaScript, no framework, no build step, no dependencies, no CDN. It must work offline and as a static page.
- Commit and push straight to `main`; HTTPS auth fails in this sandbox, so push over SSH (`git push git@github.com:JieqiangHe/minisvg.git main`). Do not create branches or PRs unless asked.
- UI text, tooltips, messages and README are English only. Never leave Chinese in the app.
- Help is kept short: one line per action, related keys grouped in one row (condensed Oct 2026).
- Code style: dense and short, no comments, match the surrounding one-liner style. Simplify without changing behaviour; don't refactor unasked.
- README ends at "... Nothing is uploaded." followed by the `**Live: ...**` line, the TBtools-II note and the licensing warning (do not use/trace others' figures as your own). Keep it that short.
- After changing `index.html`, rebuild `minisvg.plugin` with the skill, staging `index.html` with the skill's `assets/tbtools-ai.json` (it opts the plugin into the TBtools model; JDK: micromamba env `openjdk_25.0.2`, `~/.local/share/mamba/envs/openjdk_25.0.2/lib/jvm/bin`; TBtools jar: `/Applications/TBtools-II.app/Contents/java/app/TBtools_JRE1.6.jar`) and commit it. Without the jar (a cloud sandbox), see the skill's stub note.

## Architecture (names in index.html)

- `root` is the document `<svg>`; `vb` is its viewBox; `U` = mm per user unit; `Z*k` = screen px per user unit; `tx`,`ty` = pan.
- Undo: MutationObserver records into `pend`; `commit()` pushes a step (stack capped at 200 via `trim`), `revert()` undoes, `quiet(fn)` makes temporary mutations that are not recorded. Multi-commit sequences (Alt+drag copy, transform again, pasteZ, ungroupAll, held arrow keys, AI patch/import) wrap their work in `once(f,j)`: everything `commit()`ed inside collapses into one step (`j` merges into the last existing step, as held arrow keys do).
- Small helpers: `toS(q)` maps user units to view pixels (the inverse of `toU`), `q45(x,y)` rounds a vector to 45° steps (and returns the step), `cmd(e)` is Ctrl or ⌘.
- Matrices: never use DOMMatrix translate/scale/rotate (float32). Build them from arrays with `mx`, `T`, `S`, `Rot`, `about`. `lm(e)` parses the transform attribute in double precision; `ctm(e)` walks up to root. Write transforms with `setT`. `order(a)` sorts into document order, via a TreeWalker index map when the list has 64+ elements (compareDocumentPosition sorting gets slow on big files).
- Number output: `fm` (8 significant digits), `fc` (fixed 1e-5), `f6`. Untouched elements must serialise byte-identical.
- Bounding boxes:
  - `lbox(e)` is the local box, clipped by clip-path; `bbox(e)` = `mbox(e, parentCTM*lm(e))`.
  - `mbox` recurses for rotated matrices. It is exact for circle/ellipse, line/poly and straight-line paths.
  - Groups with more than 2000 descendants fall back to the loose box for speed.
  - Use `memoize(()=>...)` around batches of bbox calls.
- Selection: `sel`, `setSel(a,noRefresh)`, `refresh()`, `sb` (selection box); handles live in `H`. Locked elements (see Lock below) are filtered out of every selection.
  - Click selects the part under the pointer (`grab`); Ctrl/⌘+click selects its top-level object (`pick`). `ctx` is the group of the selection; Esc climbs it, an empty click resets it to root. Alt+click without a drag (`selBelow`) cycles through the objects stacked under the pointer (uses `elementsFromPoint` via `thru`), reporting "object 2 of 4".
  - Hover: with no drag under the Select, Eyedropper or Text tool, `hoverAt`/`hovCalc` outline in blue (`hud`) the object the pointer is over — its true outline (`outl(e)`: line endpoints, or a path's anchors with C/Q/A sampled at 8 points each via `arcPts`) as polylines, falling back to its bbox for shapes it can't read. Throttled to one calc per animation frame, or a 90 ms timeout when `hit()` last took over 12 ms; hidden over handles, scrollbars, the text editor or an already-selected object, and Ctrl held switches to the top-level object.
  - Right-click opens the context menu (`cmenu`, `#mCM`, entries in `CM`): Cut/Copy/Paste here/Paste in place/Delete, Group/Ungroup, z-order, Select the object below, Same fill/stroke, Lock/Unlock all. `cmE` remembers the event so Paste here pastes at the pointer; Ctrl+click (which also fires contextmenu on a Mac) is ignored, so Ctrl+click selection keeps working; the menu closes on outside pointerdown, click, blur, resize or Esc (which doesn't deselect). Actions `cut`, `below`, `pasteHere` exist only for the menu.
  - `hit(e)` uses `document.elementFromPoint` with `#mGW`, `#mCap` and the handles set to `pointer-events:none` (`thru(f)` toggles them around any hit-test; elementsFromPoint costs ~35 ms per call on a 150k-element file). Over a filled area, a thin line or small mark painted above within 4 px wins; the search stops after 40 ms.
  - A click on the page background starts a box select, not a move: `bd(t)` recognises a filled rect that is first among its siblings, covers at least a quarter of the page and fully contains another leaf (`down` starts a `band`, and a click without a drag selects the rect).
  - Box select `boxed(c,R,tch)`: whole groups that fit are taken, else it recurses into them; children of a group with over 2000 (`BIG`) children are measured with getBoundingClientRect. Ctrl/⌘ during the drag maps each hit to its top-level object (`pick`) before deduping. Alt+drag is touch select (`tch`): anything the box intersects is taken too, via `touches(e,R)` (a point in `inR`, or an outline segment crossing the rect with the slab test `sr`). After 60 ms of dragging, `bandPrev` previews the would-be selection — blue boxes (`D.pv` drawn by `hud`) plus a count in the status line — and switches itself off (permanently for that drag) when measuring takes over 60 ms on a large file.
  - Point editing (`ped`, like Illustrator's direct selection): a click without a drag on a corner handle, or a double-click on a shape, shows the shape's anchors as hollow squares (`data-h=a<i>`) in place of the box handles. Dragging one moves only that anchor plus the curve handles attached to it (`moveA`); Shift gives 45° steps. Esc, a new selection or a click outside ends it. `pmodel(e)` reads rect (rounded ones as arcs), circle, ellipse, polygon/polyline and path (`pparse`: absolute M/L/C/Q/A/Z, with H/V/S/T folded in; null for paths it can't read or over 2000 segments). A closed subpath's last point that repeats its start is linked to it (`anchorsOf`). On the first real drag a rect, circle or ellipse becomes a `<path>` (`toPath`, keeping id and attributes; `kps`/`kpr` keep class-styled paint). The skew mode tried before was dropped.
  - Every selection gets a centre dot (`data-h="mv"`, hidden while editing text); dragging it is a plain move, so thin lines and arrows, whose end handles sit under the arrowhead, can be moved. A click on it without a drag acts like a click on the object beneath, and with Ctrl/⌘/Shift it is ignored, so Ctrl+click on the centre still selects the whole group. A double-click with a modifier doesn't enter point editing.
  - A Shift+click (no drag) on a box or rotate handle toggles the object under it (`tog`, shared with Shift+click), since handles can cover a selected object's centre.
  - Handles sit outside selections under 24 px on screen, so small points can be dragged. `curParent()` skips clipped groups so new shapes and pastes are not clipped away.
- Lock (`lock`/`unlock`, Ctrl+2 / Ctrl+Alt+2, Select menu and context menu): writes Inkscape's `sodipodi:insensitive` (namespace declared with `xns`), so Inkscape keeps the lock. A namespace-attribute CSS block makes locked nodes `pointer-events:none` (clicks pass through to what is below); `lkd(e)` (ancestors up to root, ignoring layers) additionally filters them out of selection, Select all, All text, Same fill/stroke and the marker-panel buttons. `cands(c,lk)` skips locked candidates (so Ctrl+A and box select pass over them) unless called with `lk` — snap targets, Fit page and the import check include locked objects. `unlock` strips the attribute from everything, selects the unlocked non-layers and reports locked layers separately; locking a layer only writes the attribute for Inkscape.
- Scrollbars (`#mSx`/`#mSy`, `bars()` called from `place()`, geometry in `sbg(h)`): overlay thumbs on the canvas's bottom and right edges, grey (`--sbt`/`--sbh`) over a rounded backdrop (`--sbk`) that appears on hover, visible in both themes. They idle at 55 % opacity and wake to full (`#mView.sbOn`, set for 1.2 s by `sbWake()`) whenever the view moves or the pointer comes within 28 px of an edge. The range is the page ± 20 px (the margin `fit()` leaves) joined with the visible area, so they hide at fit or whenever the page is inside the window; thumbs are at least 32 px. Dragging a thumb pans one axis with the range frozen in `sbR`; pressing the track centres the thumb there and keeps dragging. Wheel panning stays unbounded; the range then grows to include the view.
- Auto-scroll at the edge: any move/resize/box-select drag (`edgeTick`, a rAF loop started from `move`) pans the view by up to 24 px per frame once the pointer is within 24 px of the canvas edge, shifting `D.p` along so the drag keeps working.
- Drag preview ("ghost"): selected nodes move into `svg#mGhost` inside `div#mGW`. The CSS transform goes on the div, not the svg, so text doesn't re-layout.
- Snapping: when a move drag starts, `snapSet()` stores the selection box in `D.s0` and the snap targets in `D.sn`. Targets are the page's edges and centre, plus, when there are fewer than 500 of them, the bbox edges and centres of the other objects in `ctx` (`cands` with `lk`, so locked objects snap too; root when `ctx` is a layer). `move` snaps the box's edges or centre within 5 px on screen and keeps the matched lines in `D.g`, which `hud()` draws in orange. Ctrl/⌘ turns snapping off. Shift keeps the move to 45° steps, and only the free axis snaps.
- Style copy: `styCopy(l)`/`styPaste(a)` (used by the eyedropper; no menu items or keys, Ctrl+Shift+V is Paste in place) keep `sty`: the `PS` paint values, the stroke width in pt (`ptw`), the dashes as multiples of the width, and for text its family, weight, style and size. Paste sets them on the leaves of selected groups (`klea`), so widths and sizes keep their pt. `alike(p)` (Select menu, actions `sf`/`ss`) selects every text, or every shape, whose computed fill or stroke matches the first selected leaf (`lf0`).
- Eyedropper (`drop` tool, in `down()`): a click picks the clicked object's style into `sty` and applies it to the selection, unless the click is inside the selection. Alt+click applies `sty` to the clicked object.
- Fill/stroke swatches (`#mFS` in the tool bar: `#mFF`/`#mSF` labels over transparent colour inputs `#mFc`/`#mSc`): `panel()` paints them with `fsw()`. They colour the selection through `styleSet`, or set `pen`, the fill and stroke `create()` gives new rectangles and ellipses, when nothing is selected. Lines and arrows keep fill none, and fall back to black when `pen.stroke` is none. `swapFS()` (Shift+X, action `swap`) swaps the computed fill/stroke and their opacities on every leaf, or swaps `pen`; `pnt()` writes rgb as hex and paint servers as `url(#id)`.
- Class styling (svglite): a `<style>` scopes to a class-carrying group. `ungroup()` and pasting onto another canvas snapshot the computed `KP` values (fill, stroke, linecap, linejoin, miterlimit) of the leaves (`klea`/`kps`/`kpr`) and write back inline only what would change; `styleSet` on a group skips leaves whose fill/stroke computes to none. `klea(g)` and `leaf(g,f,cap)` walk leaves with a TreeWalker (`twalk`) that never enters defs/clipPath/mask/marker/pattern/symbol; `setSts(e,kv)` writes several style properties at once into the style attribute (order-preserving) and removes their presentation attributes.
- Text editing: `edit()` / `finish()` use a contenteditable `.ed` overlay. As in Illustrator, Esc finishes (`finish(true)`; Ctrl+Z undoes it) and switches to the Select tool and Enter starts a new line; there is no cancel key. Ctrl+Shift+= / Ctrl+Alt+Shift+= superscript and subscript while editing.
- Font field `F.ff` (`<input list="mFonts">`): a datalist filters by the current value, so on focus the value moves to the placeholder and `#mFonts` is rebuilt from `FONTS` plus the fonts the document's texts use; on blur an untouched field gets its value back. Focusing it also calls `localFonts(1)` (Chrome/Edge `queryLocalFonts`; the click is the user activation the first permission prompt needs; failures are silent; without it, or when refused, as in Safari and Firefox, the ~120 common Mac/Windows/Linux/CJK names in `CAND` are tested with `hasF`, a canvas width check against monospace, serif and sans-serif), which adds the installed families to `sysF` (deduplicated, sorted, dot-names dropped); at startup `localFonts()` loads them only if the permission is already granted. The Safari fallback was confirmed on the user's Mac (Oct 2026); the Chrome permission prompt and JxBrowser are untested. `<sup>`/`<sub>` become `tspan style="font-size:65%;baseline-shift:super|sub"`.
- AI chat panel (`PROMPT` holds every prompt string; `ask` orchestrates): providers and models live in the `AI` object — each entry is `[url, ...models]`; Glm has `glm-5.3-flash`/`glm-5.3`, Gcp (GLM Coding Plan, `nameOf` adds " Coding Plan") `glm-5.3` on `/api/coding/paas/v4`, Ds `deepseek-flash`/`deepseek-v4-pro`. Gcp was added because bigmodel.cn now issues Coding Plan keys separately from standard keys, and the standard endpoint bills only the account balance (429, code 1113, when it is empty; Oct 2026); whether the plan covers the flash/vision model is unknown, so Gcp has none. `VIS` is the set of models that can see images (the two flashes). Values in the dropdowns are `Prov:model` strings; `who` parses them, `nameOf` labels them, `canSee` checks vision, `drawTo()` reads Draw with (`#mModel`), `reader()` reads Read images with (`#mVis`; `self` = the draw model), `looker(c)` picks who reads an image (the reader, or the draw model itself when it can see). Keep both dropdowns — new models may be added; do not simplify them away.
  - Settings (`#mCfg` details): "Read images with" (`#mVis` + its thinking effort `#mThinkR`), "Draw with" (`#mModel` + `#mThink`), the route sentence `#mRoute`, one key row per provider (`#mKeyGlm`/`#mKeyGcp`/`#mKeyDs`, shown via `label[data-p]`) and the endpoints folded under `#mAdv` (`#mEpGlm`/`#mEpGcp`/`#mEpDs`). `cfgSync` shows only the rows the current route needs, disables "Same as Draw with" when that model can't see images, and opens the panel when a key is missing. Defaults for a new visitor (user's choice, Oct 2026): Draw with GLM-5.3 at High, Read images with GLM-5.3 Flash at Max — cfgSync picks the draw provider's first vision model whenever "Same as Draw with" is disabled, else (Gcp) the first enabled reader.
  - Requests: `call(to,msgs,o)` — one code path for every model; TBtools via the bridge (below), the rest fetch with SSE parsed by the `sse` generator. No `max_tokens` is sent, so each API's default applies (a fixed 32768 used to cut long replies off silently; the user chose the defaults over hard-coding each model's ceiling, Oct 2026). `reasoning_effort` comes from the Think fields; thinking stays on (glm-5.3 reportedly rejects `thinking` disabled).
  - Drawing: `draw(to,base,o)` streams the reply into a `bubbleUI` bubble (waiting text, thinking text capped at ~20k chars, `stage` progress labels, `note` status messages, token usage from `usage` — "42 s · 12,345 output tokens (3,456 thinking)"). A reply cut off (`finish_reason` `length`; from TBtools, which gives no reason, an `<svg`/`<patch>` without its closing tag — `openP`/`pt0`) is continued up to 3 times at `reasoning_effort` low via `PROMPT.con` and `join` (drops a leading code fence and any repeat of the partial's end; a continuation that restarts with a whole `<svg`/`<patch>` replaces the partial); a cut while still thinking retries once at low. Still cut after that shows a cut-off note and keeps the part that was drawn; errors put the question, files and images back into the box.
  - Reading images: an attached image is first described by a model that can see (`look`, `PROMPT.look`): JSON items on a 0-1000 grid (rects, ellipses, lines/arrows, paths, texts with exact transcription, pictures, axes with ticks, paint, panel name "g", "?" for doubts). `mmSpec` rescales that into whole tenths of a millimetre, and `PROMPT.units`+`PROMPT.whole` send the description to the drawing model (the bubble shows "What <model> saw: N items" via `ui.spec`). When the description names 2+ panels and holds 60+ (`CHUNK`) items and drawing goes over an API (not TBtools), `panels`/`drawPanels` draw every panel in parallel (own prompt and viewBox window per `PROMPT.panel`, quiet — no streamed text, only `stage` counters) and `asm` stitches them into `p1…` groups (ids re-prefixed and relinked, transform per panel window), reporting panels that failed.
  - Patch: when the AI figure is still on the canvas, nothing is attached and nothing selected, the current SVG (`frag([aiG])`) goes along with `PROMPT.cur`, which asks for a `<patch>` instead of a full SVG. `patch(t)` applies it as one `once()` undo step: an element carrying an existing id replaces that element (the figure root keeps its transform and label), `<delete ids="…"/>` removes, `<add after=…|before=…>` inserts; new ids are uniquified, a cut-off patch is refused outright. `refs`/`deps` (was just `deps`) split live-reference walking from cloning.
  - Compare: a redraw from an image remembers it in `refImg` (the data URL, its pixel size and the viewBox of the drawn SVG, `vbOf`). The Compare button (`ask({cmp:1})`) renders the figure cropped to that region (`frag` with `refBox()`), composes it beside the original behind a red bar (`side`), has the reading model list up to 10 differences (`PROMPT.check`) and sends them back as a fix request with boxes mapped into figure coordinates.
  - History: `selPart` (limit `SELMAX` 200k chars) attaches a selection as SVG, with an image fallback for TBtools; after sending, the attached SVG text is replaced by a note. `past(h,vis,kl)` shapes what is resent: images are kept only for models that can see (else flattened by `flat` to `[image]`), and only the last assistant SVG stays in full, and only while the figure it describes is still live.
  - `land` places the reply: Insert copy, Replace selection (`aiSwap`, was `swap`), Open as new; stores `refImg.vb`; cut or missing-panel notes; then the Compare button. `svgOf` grabs the full or partial SVG, adds missing `xmlns:*` (`XNS`) and, if XML parsing fails, retries the string as HTML (`fixSvg`) before giving up.
  - The system prompt (`PROMPT.sys`) asks for compact SVG — a viewBox in tenths of a millimetre so coordinates are whole numbers, Arial `<text>`, relative path commands, `<polyline>` for data series, shared attributes on a `<g>`, short ids, no comments/metadata/indentation — while keeping every element. The user chose continuing plus compact writing over raising `max_tokens`, and turned down `<use>` (copies can't be edited one by one; Oct 2026).
  - TBtools model (PR #19 by CJ-Chen, the TBtools author; confirmed working in TBtools by the user, Oct 2026): when `tbBridge()` (`window.tbtools.ai`, checked once at startup) exists, `Tb` is added first to both dropdowns and picked unless a saved choice says otherwise; it needs no key and hides the key/endpoint/Think rows (`cfgSync`). Text goes through the same `call`: `chat(messages,{onDelta})` with `tbFit` (system prompt plus at most 19 messages within `TBMAX` 32,000 characters, images flattened to `[image]`, leading assistant messages dropped); an image (or a selection too large for text, as its preview) goes to `chatImage(prompt,dataUrl,mime)` via `tbPrompt`, which folds history, files and selection into one prompt. Both carry `requestId`, collected in `rids` so Stop aborts them all (`tbWhy` maps `aborted`, `denied`, `busy`, `closed`, `invalid`, `too_many`, `too_large`, `empty` to messages). A normal browser never shows the option. The bridge gives no progress, so a bubble reads "Waiting for the reply…" with a seconds counter until text arrives.
- Page: `syncPage()` and `setPage(x,y,w,h)` (undoable). A new canvas is named `untitled.svg` (the New dialog's Name field `#mNN` sets it; `.svg` is added, characters not allowed in file names become `_`); the name shows in the tab title and starts the export names. There is a side-panel preset `#mPg`, and the New dialog `nd()` uses presets `#mPre` and radios `mOr`.
  - Preset rule: a preset keeps its own orientation, except that a portrait preset is flipped while landscape is selected.
- Export:
  - `svgText()` gives the clean SVG (via `finish(true)` + `prolog` + XMLSerializer).
  - `outName(ext,tag='')` builds `name[_tag]_YYMMDD_HHMMSS` (`stamp()`, local time) in lowercase, first stripping one or two trailing `_\d{6}` groups so re-saving doesn't stack stamps; PNG and JPG are `name_300dpi_YYMMDD_HHMMSS.png`/`.jpg`.
  - `png(dpi,j)` and `pdf()` both use `vb.w*U` for mm. `png` renders on white; PNG gets a `pHYs` chunk (`phys`), and with `j` it writes a JPG at quality 1, where Chromium keeps full colour (4:4:4; 0.95 and below use 4:2:0, which blurs coloured text and thin lines), with `jfif` setting the JFIF density to the dpi (Chromium writes units 0, 1:1) or inserting a JFIF segment when there is none. File menu: PNG and JPG at 300 and 600 dpi. `pdf()` is a hidden iframe with `@page{size:Wmm Hmm;margin:0}` plus `print()`.
  - Ctrl+S (`save`) keeps the `showSaveFilePicker` handle in `fh` after the first save and writes back to it; `load()` clears `fh`; without the API, or when the write fails, it falls back to `dl()`.
- Select all in TBtools: its JxBrowser runs the browser's own Select All on Ctrl/Cmd+A (the whole interface got highlighted) even though the keydown handler maps Ctrl+A to `A.all`. A `selectstart` listener cancels any selection that starts outside inputs, the text editor and the chat log while no dialog is open, and when no pointer is down (`pdn`), i.e. a select-all command, runs `A.all`. Untested in TBtools itself; `document.execCommand('selectAll')` reproduces it in Chromium.
- Ungroup removes one level, as in Illustrator and Inkscape. `ungroupAll()` (Alt+click Ungroup, Ctrl+Alt+Shift+G matched on `e.code` so ⌥ on a Mac works) repeats it until no groups are left, as one undo step; a clip wrapper that `ungroup` creates around a child with its own clip-path is kept, or it would loop.
- Clipboard: `copyOut` also writes the selection as SVG (or a note) to the system clipboard, remembered in `lastOut`; a paste of text starting with `<svg`/`<?xml` that is not `lastOut` is imported. `reid()` renames ids in a subtree and relinks its internal `url(#…)`/href references, so duplicates stay self-contained.
- Pseudocolor menu after SVG Chat (a trial feature, unlabelled as such for users; ported from a channels demo): `pseudo(n)` tints the selection with a shared `<filter id="msbLut<Colour>">` (`lut`, `LUT`; gray first by .299/.587/.114, then times the colour; `pseudo('')` removes the filter). `mergeCh()` copies 2 to 7 images into a group 5 mm right of the selection, each scaled to the first and set to `mix-blend-mode:screen`, over a black rect, in a group with `isolation:isolate`; `upc` skips clipped parents. Deliberate, keep them: `color-interpolation-filters="sRGB"` (linearRGB darkens mid-grays vs ImageJ/Illustrator), filter region 0 0 1 1 (the default +10% grows Inkscape's bbox), and isolation + black rect (else Screen mixes with the white page, or shows what is underneath).
- Black screen after switching tabs during an AI reply (reported in Safari, not reproduced here): `visibilitychange` drops `will-change` on `#mStage`/`#mGW` while hidden, so the large composited page layer is released, and on return restores it and repaints (`place`, `hud`). The streamed reply is drawn at most once per animation frame (`upd` via `raf`; thinking text batched in `rsn`), so a hidden tab only accumulates text.
- Preferences in localStorage: `msbTheme` (first visit is light, then the last choice is remembered), `msbRulers` (rulers start hidden and show only after the user turns them on, Oct 2026), `msbGrid`, `msbChat` (SVG Chat panel), and the AI panel's `msbDraw` (the Draw with model, `Prov:model`), `msbVis` (Read images with, or `self`), `msbThink`, `msbThinkR`, `msb<Glm|Gcp|Ds>{Key,Ep}`. A legacy `msbAi` together with `msb<Prov>Model` is read once at startup and migrated to `msbDraw`.
- Actions: buttons use `data-a` mapped in the action object (`cut`, `below` and `pasteHere` exist only for the context menu); fields use `data-f` and are reached as `F.<name>`. Tools use `data-t`; keys follow Illustrator: V select, T text, M rect, L ellipse, \ line, I eyedropper (`drop`), C crop, plus A arrow and B inhibit (Illustrator has no such tools).
- Tool bar order: everything above the separator under the colour swatches is settled and stays; new, trial tools go below it. This is a developer convention only: don't mention it in the UI, help or README.
- Shortcuts follow Illustrator. Punctuation keys (brackets, = -, 0 1 2, ', . ,) are matched on `e.code`, letters on `e.key`. Ctrl+[ ] and Ctrl+Shift+[ ] reorder (Home/End/PgUp/PgDn are kept as aliases); Ctrl+0/1/=/- fit, 100 %, zoom (`zv`, also Alt+wheel); Ctrl+R rulers, Ctrl+' grid; Ctrl+2 lock, Ctrl+Alt+2 unlock all; Ctrl+Shift+A deselect; Ctrl+Shift+S save as (`svgAs` clears `fh`); Ctrl+Shift+P place (Ctrl+I kept); Ctrl+P PDF; Ctrl+Shift+. / , change the font size by 1 pt (`fsz`); D default colours (`dflt`); Shift+X swap. Alt+click cycles through stacked objects, Alt+drag box-selects by touch, right-click opens the context menu. The browser keeps Ctrl+N/T/W, so New has no shortcut.
- Transform again: `keep(M,b,c)` stores the last drag, nudge or panel transform in `again` as a matrix relative to the box centre (`c` marks an Alt+drag copy). `tAgain()` (Ctrl+D) re-applies it about the current selection's centre, duplicating first via `dup()` when `c` is set, and merges the steps into one undo. Alt held at pointer-up on a move turns it into a copy: `up(ev)` puts the originals back, `dup()`s them and moves the copies.
- Paste variants: Ctrl+V at the cursor, Ctrl+Shift+V in place on top (`paste(true)`), Ctrl+F / Ctrl+B in place just in front of / behind the selection (`pasteZ`, which moves the pasted nodes next to it, rewriting their transforms if the parent differs).
- Marker heads: the Appearance field Head (`F.hd`, %) calls `heads(p)`. For each marker the selected leaves use (`MP`), `hmk(id,p)` returns the base marker at 100 % or a sibling clone `<base>_h<p>`: the base's attributes, overflow visible, and its children (re-id'd) in a `<g>` scaled about refX/refY. A clone made from a clone (base gone) scales by p/current. `_h` clones left unused are removed. The panel reads the % back from the id suffix. `heads` also stores the % in `pen.head`, which `create()` gives new arrows and blunt ends (via `hmk`); with nothing selected the Head field edits `pen.head`.
- Crop (`crop` tool, `crop(img,a,b)`): dragging across an `<image>` (the selected one, else the one under the drag start) clips it with a `clipPath id="crop…"` holding one rect in the image's own coordinates. A later crop edits that rect if no one else uses it; a box covering the whole image removes the crop. A clip-path the image already had is chained onto the new clipPath (`clip-path` on the clipPath). Pixels are never touched.
- Pitfall: global name collisions. A helper named `pick` once broke selection's `pick()`, so grep before adding a name.
